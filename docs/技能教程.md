# 技能中心：给模型一份清楚的工作方法

适用于1.6.0。技能是文字规则，不训练模型，也不自动运行代码。工具负责实际执行；所有本地和云模型使用同一套技能与工具功能。

## 使用与管理

打开“技能中心”，可以新建、编辑、复制、删除技能；名称、简介、版本、建议工具和Markdown规则分别填写。正文上限12000字节，编辑时显示用量和右侧阅读效果。默认仅保留一个通用示例“资料核对与结果整理”，可复制后自由改写。

聊天输入框“＋→使用技能”可选择最多两个技能。未选中的技能不占本轮上下文。规则会在发送时记录版本和内容快照；之后编辑或删除技能不会改变已排队任务的规则。

技能里的“建议工具”仅说明任务需要什么，用户仍需自行勾选。工具未启用或执行失败时，模型应如实说明，不能声称运行了代码或生成了文件。

## 如何写一份容易执行的技能

建议包含四部分：目标、输入、步骤、输出。用具体动作和可检查的结果，缺失资料写“待确认”，不预置企业原文、密钥或私人答案。

```markdown
# 目标
整理用户提供的设备维护资料，生成可核对的待办清单。

# 输入
用户选定的附件、明确要求和已启用工具。

# 工作步骤
1. 查看文件结构，确定资料范围和版本。
2. 提取明确的任务、时间、责任人；缺失字段保留待确认。
3. 需要计算时使用已启用工具，保留输入和单位。
4. 生成表格后重新读取核对，不编造原文中没有的信息。

# 输出
任务、来源位置、负责人、时间、待确认项。
```

## 导出、导入与学习

- 导出ZIP：包含根目录manifest.json、SKILL.md、README.md，适合保留名称、简介与建议工具。
- 导出MD：只包含规则正文，便于给人或其他AI阅读和修改。
- 导入MD/ZIP：创建新的独立副本，不覆盖现有技能；MD应为UTF-8。
- ZIP只接受上述文字文件，不接受脚本、任意目录或安装步骤。规则内容并不会被当成程序执行。

最简单的学习方式是导出通用示例，修改SKILL.md，再导入测试。manifest.json示例：

```json
{
  "id": "evidence-summary",
  "name": "资料核对与结果整理",
  "description": "先核对来源，再整理结果。",
  "version": "1.0",
  "requires_tools": ["read_attachment", "python_run"]
}
```

导入时会分配新编号，避免覆盖同名规则。

## 配合文件读取、Python和Office

“读取本对话附件”使用当前有效分支已发送的附件编号，先列清单再按实际编号读取；ZIP可先列条目后分段读取。返回片段不代表已经处理全文。

Python适合计算、解析和生成文件。原件副本在INPUTS列表中，包含编号、名称、路径与SHA256。Office COM提取文字可能另有text_path，不应把提取文字视为保留了原件全部格式、图像和公式。

Office操作器适合结构读取、内容/版式编辑、插图和实际预览。技能可写“先读取结构，再编辑指定对象，保存后检查”，调用的实际参数应以工具说明为准。

每条用户消息默认累计最多50次实际工具调用，可在设置调整；技能不会单独增加额度。失败尝试也计数，自动时间注入不计数。模型说“已核验”不能代替工具结果和实际文件检查。
