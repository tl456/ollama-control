## 预设：整理刚度 Excel 表格

本预设不含固定产品编号、企业标准、专用 DAT 解析器或参考答案。模型可以自行观察本次 DAT/ZIP 的结构，决定如何解析、计算和生成 Excel。不同设备导出的 DAT 可能完全不同，格式不明确时应先提问，不强行套用。请提供任务、需要采用的条件和标准；缺失内容保留“待确认”。

关键实测数应注明附件编号、文件/ZIP条目、记录组及字段/行；计算结果保留输入、公式和单位。数值确实出现在文件中，也不代表样件、方向、频率、振幅定义、预载或试验阶段匹配。相对目标偏差与耐久前后变化不能混用。模型仍可能出错，不能保证零幻觉。

推荐任务示例：“请先检查这些合成 DAT 的字段和记录分组，列出可采用的数据及条件歧义；确认后整理 Excel。没有标准不要判断合格。每个关键值注明来源，保留复核和待确认项，保存后重新读取核对。”

## 原始附件，不依赖聊天截断

“读取本对话附件”只访问当前有效对话分支已经发送的附件编号，不接受任意路径或其他对话的附件。未发送的草稿附件、未来待发消息、被排除消息不进入本轮范围。

工具先使用 `{"action":"list"}` 查编号，再传 `attachment_id`。ZIP 先列条目，之后 `{"action":"read","attachment_id":"实际编号","member":"清单内确切文件.dat","offset":0}`。每次最多返回 12000 字符，按 `next_offset` 继续；片段不是全文。ZIP 不自动解压、不执行其中程序，限制 1 万条目、总展开 100 MiB、单条目 20 MiB、异常压缩比、重复/越界/加密/链接条目。

Python 默认获得本分支授权附件的完整副本，最多 20 个、含提取文字合计 100 MiB。超过时用 `attachment_ids` 明确挑选。`INPUTS` 是列表，每项含 `id`、`name`、`path`、`sha256`；`path` 指向本次 `inputs/` 原件副本。Office COM 提取文字另有 `text_path`；副本是否可由 openpyxl 打开仍受实际格式和企业加密约束。不要把提取文字当作保留了全部格式、公式或图像的原始 Office 文件。

```python
from pathlib import Path
print(INPUTS)
item = INPUTS[0]
print(Path(item.get("text_path", item["path"])).read_text(encoding="utf-8")[:1200])
```

ZIP 可在正常 Python 中按已确认条目名读取，优先 `ZipFile.read()`，无需 `extractall()`。附件内容不自动授予联网、安装依赖、系统命令或其他本机文件访问权限。

## 轻量证据记录，不是合格认证

```python
from workbench import verify_text, record_calculation, export_evidence
check = verify_text(INPUTS[0]["id"], "实际文件中的一段原文")
print(check)
record_calculation("相对目标偏差", {"measured": 101, "target": 100},
                   "(measured-target)/target", (101-100)/100)
export_evidence()
```

`verify_text` 检查副本哈希和原文出现位置，返回 `literal_found` 或 `not_found`；ZIP 另传 `member`。它不判断条件是否匹配，也不自动证明“合格”。Office/图片使用已提取文字时会明确标记来源表示，OCR 或提取本身仍可能有误。`record_calculation` 保存提供的输入、公式与结果，不假称已独立重算。`evidence.jsonl` 和导出的复核 JSON 可下载，受信任代码能修改运行目录，因此不是防篡改审计。

可正常 `import openpyxl` 生成 Excel，保存到当前运行目录。建议把结果、来源、计算依据、待确认项分表或分列；保存后 `load_workbook()` 再读，核对行数、记录和写入位置。工具返回实际生成文件的下载链接和 SHA-256。要在下一次 Python 调用复读文件，传前次结果的 `previous_run_id`，普通输出文件会复制到 `previous/`，只能引用本对话已有运行。

普通回合最多 4 次工具调用；选技能时最多 6 次，Python 最多 3 次（首次及两次修正）。达到上限后应交代进度和缺项，下一条消息继续，不无限循环。模型说“已核验”不是系统证据，界面应以实际工具结果、文件和复核范围为准。
