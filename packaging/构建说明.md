# 从公开源码构建 Windows 发行包

目标环境：Windows 10/11 x64、Python 3.12、官方 Inno Setup 编译器。源仓库包含程序和网页资源，不包含个人配置、模型、虚拟环境、Ollama 显卡库或独立 Python 运行时。

仅运行源码时，按仓库 README 安装应用依赖后运行 `python main.py`。以下步骤用于制作含 9B、4B、0.6B 和完整显卡运行库的离线发行文件夹。

## 1. 构建依赖

在仓库根目录打开 PowerShell，并激活一个新的 Python 3.12 虚拟环境：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-build.txt
```

`requirements-build.txt` 引用 Windows / Python 3.12 的固定版本快照 `requirements-lock.txt`，包含 PyInstaller。它固定包版本，未包含每个 wheel 的摘要，不能作为依赖来源的密码学证明。请从官方包源安装，避免复用带个人可编辑安装、企业保护文件或未知依赖的环境。

NumPy 2.5.4 使用仓库中 `packaging/public-licenses/numpy-2.5.4/LICENSE.txt` 的官方公开原文，构建时检查固定 SHA-256。若更换 NumPy 版本，应同时重新核对上游许可和构建配置，不使用本机私有路径回退。

## 2. 准备公共离线输入

以下 `D:\BuildInputs` 只是可替换的示例目录，不是软件固定路径。四类输入必须与构建输出分开：

| 参数 | 需要的内容 |
|---|---|
| `--ollama-dir` | 官方 Windows Ollama 程序目录：`ollama.exe` 和完整 `lib/`，保留所有显卡后端 |
| `--python-exec-dir` | 官方 CPython 3.12 x64 embeddable 运行时，含 `python.exe`、DLL、标准库 ZIP、`LICENSE.txt` 及代码工具所需公开依赖 |
| `--tokenizers-dir` | `qwen35/tokenizer.json`、`qwen35/LICENSE`、`qwen3-embedding/tokenizer.json`、`qwen3-embedding/LICENSE` |
| `--models-dir` | 只从中读取 `qwen3.5:9b`、`qwen3.5:4b`、`qwen3-embedding:0.6b` 的 manifest 及被引用的 blob，不复制其它模型或文件 |

Ollama 与 Python 请从 [Ollama 官方发布](https://github.com/ollama/ollama/releases)、[Python 官方 Windows 下载](https://www.python.org/downloads/windows/)取得，并由构建者核对官方摘要和 Windows 签名。若 Ollama 目录没有 `LICENSE` / `LICENSE.txt`，另外准备对应官方版本的许可证，并传入 `--ollama-license`。

官方分词资源分别来自 [Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B)、[Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)。保留实际下载版本、摘要和许可；下载地址或分支名本身不能证明具体字节的来源。嵌入模型声明为 Apache-2.0 时，可附其模型卡的许可声明和 [Apache-2.0 原文](https://www.apache.org/licenses/LICENSE-2.0.txt)。

模型可在已安装的官方 Ollama 中用 `ollama pull` 准备上述三个名称，然后把其模型存储目录作为 `--models-dir`。脚本按 manifest 检查每层大小与 SHA-256，但这种一致性检查不能替代官方来源核对。

独立 Python 运行时应包含 `openpyxl` 与其依赖，供代码工具生成 Excel。可用构建环境的 pip 将公开依赖安装到独立运行时的 `Lib/site-packages`：

```powershell
python -m pip install --target D:\BuildInputs\python-exec\Lib\site-packages -c requirements-lock.txt openpyxl
```

按 CPython embeddable 的官方说明，在该运行时的 `python312._pth` 中保留标准库与当前目录，加入 `Lib/site-packages` 并启用 `import site`；安装依赖时应保留其 dist-info 与许可证。先独立测试 `python.exe -I -B -c "import openpyxl; print(openpyxl.__version__)"`。普通 Python 主解释器和这个用于代码工具的离线解释器是两份不同的运行环境。

## 3. 冻结、准备与核对

```powershell
python scripts/build_release.py freeze
python scripts/build_release.py prepare --ollama-dir D:\BuildInputs\ollama --ollama-license D:\BuildInputs\Ollama-LICENSE.txt --python-exec-dir D:\BuildInputs\python-exec --tokenizers-dir D:\BuildInputs\tokenizers --models-dir D:\BuildInputs\models
python scripts/build_release.py check
```

默认输出 `dist/LocalAIStudio`。可在每条命令中一致指定 `--output-dir <新目录>`；准备/核对阶段也支持 `--frozen-dir <已冻结程序目录>`。冻结阶段要求新输出目录，不递归删除已有发行程序或资料。

冻结生成无控制台的 `LocalAIStudio.exe` 与工作进程 `LocalAIWorker.exe`。准备阶段只加入显式公共输入和三个预设模型，保留 Ollama `lib/` 的全部文件；不会裁剪 CUDA、ROCm 等后端。输入中的链接、保护头、根级个人资料或凭据样式文件会报错。它不会读取应用配置、聊天或附件，不会自动下载、执行 Ollama 或调用模型。

准备结果生成：

- `dist/LocalAIStudio/docs/release/bundle-manifest.json`：公共运行库、模型层与 manifest 的相对路径、大小和 SHA-256，不记录输入的本机绝对路径。
- `dist/LocalAIStudio/docs/release/ollama-control-版本-source.zip`：含 MIT、源码、网页、教程和测试的完整源码包。按公开目录白名单选择，包含新公开文件；排除配置、聊天、附件、审计、模型、运行时、构建输出和 Git 元数据。源码中的保护头、明显凭据和不可读文本会阻止准备。
- `dist/build-metadata/model-files.iss`：只含三个预设模型的安装条目；大层不重复压缩，模型在卸载时保留。
- `dist/build-metadata/build.json`：版本与公开输入计数。

`check` 再次读取清单核对摘要、runtime/models 文件集合以及源码 ZIP 的精确成员、CRC 和 SHA-256。源码 ZIP 会随安装版和解压版一起交付。构建输入和输出必须是专用的干净目录；此入口不是通用的数据泄露检测器，发布前仍须扫描完整发行目录、检查第三方许可、真实安装运行和另一台电脑的兼容性。

## 4. 完整安装包

```powershell
python scripts/build_release.py installer --iscc "D:\BuildTools\Inno Setup\ISCC.exe"
```

`--iscc` 指向自行安装并核对来源的官方编译器，也可将它加入 PATH。该命令只运行编译器，不运行生成的安装器。

输出到 `dist/installer`。数据卷上限固定为 **1,900,000,000 字节**，小于 GitHub Releases 每附件 2 GiB 的上限；EXE 与所有 BIN 必须放在同一目录使用。构建后还会检查每个输出文件小于 2 GiB，并生成 `SHA256SUMS.txt`。不要把模型或大运行库提交到 Git 仓库。

也可在四类输入就绪时，用 `all` 加上述相同参数一次执行 **freeze → prepare → installer → portable**。其中 `portable` 生成下一节的完整 ZIP64 解压包。首次正式分发前仍应独立安装/退出/卸载、核对模型与保留升级行为；CI 的合成测试不代表已执行这些本机集成验证。

## 5. 完整离线解压包

```powershell
python scripts/build_release.py portable --output-dir dist
python scripts/build_release.py portable-check --output-dir dist
```

`portable` 要求先完成 `freeze` 和 `prepare`，会再次核对已准备的完整程序目录。输出到 `dist/portable`：

- `本地智能工作台-版本-完整离线解压包.zip`：标准 ZIP64，顶层统一为 `LocalAIStudio/`，包含程序、全部官方运行库、三个预设模型和源码 ZIP。使用存储模式，不重新压缩大模型。
- `portable-manifest.json`：全部 ZIP 成员的路径、长度和 SHA-256，以及整个 ZIP 的长度、摘要。
- `SHA256SUMS.txt`：完整 ZIP 的 SHA-256。

写入完成后会逐成员完整回读，校验 CRC 和 SHA-256，再计算整个 ZIP 摘要。`portable-check` 只依赖 ZIP 与相邻清单，不要求原始程序目录仍存在；能检查后续复制是否损坏。已有便携输出不会被覆盖，失败的构建输出应先检查。

本地交付可保留这个单个完整 ZIP，用户解压后进入 `LocalAIStudio` 文件夹运行 `启动.bat`。运行前不要只抽取 EXE；运行库和模型必须一并保留。

## 6. GitHub 便携分卷与免 Python 合并

完整 ZIP 通常超过 GitHub Releases 的单附件 2 GiB 限制。对**公开版**完整 ZIP 执行下面命令，每片固定最多 **1,900,000,000 字节**；本地单 ZIP 无需分卷。

```powershell
$portableMetadata = Get-Content -LiteralPath dist/portable/portable-manifest.json -Raw -Encoding UTF8 | ConvertFrom-Json
python scripts/split_release.py split-portable --archive (Join-Path dist/portable $portableMetadata.archive) --output-dir dist/portable-parts --expected-sha256 $portableMetadata.sha256
python scripts/split_release.py verify-split --output-dir dist/portable-parts
```

`--expected-sha256` 将分卷输入与已验证的便携包清单连接起来。分卷过程中计算单片与整体摘要，结束后独立回读所有分卷验证；`verify-split` 按清单白名单顺序再次流式核对单片和整体摘要，不创建第二份大 ZIP。输出目录必须为空，不覆盖已有发行。

将 `dist/portable-parts` 中**所有文件**作为该版本 Release 附件上传：

- `.zip.001`、`.zip.002`……全部分卷；
- `portable-parts.json`：顺序、单片长度与摘要、完整 ZIP 长度与摘要；
- `Merge-Portable.ps1` 和 `合并便携包.cmd`：Windows 自带 PowerShell/.NET 合并工具；
- `分卷使用说明.txt` 和 `portable-parts-SHA256SUMS.txt`。

普通用户把这些文件放在同一文件夹，保留原文件名，双击 `合并便携包.cmd`。它逐片核对，再回读完整输出的 SHA-256；成功后才得到完整 ZIP。脚本不联网、不安装、不运行工作台、不覆盖已有 ZIP。缺片、乱序或摘要不符会停止，保留原始分卷，只清除本次创建的临时输出。合并需要额外一份完整 ZIP 的空间，解压还需要程序目录所占空间。

CMD 的执行策略参数仅作用于本次 PowerShell 进程，不修改机器或用户级策略；企业强制策略仍应遵守。脚本使用 FileStream 与 SHA-256，不要求安装 Python 或第三方解压软件来合并。用户也可在 PowerShell 中通过 `-OutputDirectory` 指定另一个输出目录，具体命令在随附说明中。

安装版与解压分卷可同时附在同一个 Release；安装 EXE/BIN 与 `.zip.001` 分卷是两套独立交付，用户任选其一。不要把私有本地署名包或私有构建报告混入公开上传目录。

## 7. CI 范围

`.github/workflows/tests.yml` 在 GitHub Windows runner 上安装固定依赖并执行合成单元回归。它不使用云密钥、真实模型或 Office COM，不制作十余 GB 离线安装包。发布与分卷测试使用小型合成 ZIP，覆盖 ZIP64、CRC、摘要、缺片、顺序、路径和真实 PowerShell 合并；这不代替完整大包的实际核验。官方 tokenizer 未准备时，相关真实分词集成测试须明确跳过。Action 使用已核对的官方发布提交，并仅授予只读仓库权限；不持久保存 checkout 凭据。
